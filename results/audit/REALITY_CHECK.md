# Reality check (S1-S5, v1 config `de199d6c8d69`, git `f1ea178`)

Figures: `reality_check_fractions.png`, `reality_check_artefacts.png`, `artefacts_by_batch.png`, `overlays/` (6 tiles, 2 per batch). Classes are grey-level classes 0/1/2; units are px; pixel size unconfirmed. No verdicts here.

1. Data: 31 images (Batch_1 7, Batch_2 7, Batch_3 17), 93 TIFFs; 27 images have BSE+ETD+Inlens, 4 have BSE+Inlens+SE; every image has an Inlens view (img_xgj4xftb_Inlens.tif was missing from the repo's Drive listing and was added from the shared folder). 4329 tiles (1024 px, stride 512, plus one edge-anchored tile per row/column so the whole cropped field of view is covered), 1443 of them BSE (39-52 per image).
2. Class fractions (per-image mean over tiles): batch medians c0 = 0.095 / 0.098 / 0.102, c1 = 0.829 / 0.811 / 0.804, c2 = 0.089 / 0.092 / 0.097 (Batch_1 / 2 / 3). The largest gap between batch medians is 0.3-1.0x the median within-batch IQR, so **no batch separates on fractions beyond its own spread**.
3. Three images carry most of the class-2 spread: 4ih2ggld and 5n1q8atc (Batch_1) at c2 = 0.21-0.22 and r17byphk (Batch_2) at 0.14, roughly 2x the other 28 images (0.06-0.13).
4. Threshold sensitivity: scaling the per-tile multi-Otsu thresholds by 0.9 / 1.1 moves c2 by a median 0.041 / 0.024 and c0 by 0.009 / 0.015 per image, i.e. the +/-10 % error bars are as large as or larger than every between-batch gap.
5. Per-tile multi-Otsu is unstable on tiles without bright particles: upper threshold t1 ranges 47-170 (median 82; 3 tiles above 120); the 31/1443 tiles with t1 < 60 report median c2 = 0.29 vs 0.08 elsewhere (corr(t1, c2) = -0.57; on such tiles class 2 outlines flake texture, see `overlays/`). Candidate for an S4 challenger (per-image thresholds or a floor on t1); v1 left as specified.
6. Artefacts: curtaining_score (BSE) and edge_charging (Inlens) do not separate batches (median gaps 0.6x and 1.0x the within-batch IQR). noise_sigma and sharpness (BSE) do: Batch_3 median noise 37.7 vs 46.3 / 44.4 (gap 3.2x IQR; sharpness gap 3.3x), and Batch_3 splits into a low-noise cluster (7 images, sigma 29.7-31.4) and a high-noise cluster (10 images, 37.2-45.5).
7. Images group by (height, XResolution tag): 13 groups, each with near-identical noise and sharpness, and 5 of them span two or three batches (e.g. height 2080 / tag 126998864/125 holds images from all three batches). This looks like acquisition sessions that cut across batch labels; it must be checked with Polaron (consultant C1) and means S7 needs artefact ablation plus a leave-one-group-out check, not only leave-one-image-out.
8. Contradictions with `docs/READ/Dataset First Look.md`: widths are 6960-7000 px, not a uniform 7000; the coloured edge line is in column 0 (21 files) as well as the right edge (18 files), the 8 px crop covers both; the resolution tag has 13 distinct values, 24.9992–25.0006 nm/px if the tag unit is cm, and was written by tifffile, so it is not microscope metadata.
9. Wall time (8 CPU cores): download ~3 min (93 files, 1.7 GB); audit 12 s; tiles 16 s; artefacts 57 s; segment 75 s; kpi + sensitivity + overlays 89 s; figures 1 s.
10. Review fixes applied before these numbers (Devin Review on PR #1): the tile grid now adds an edge-anchored tile when the stride grid stops short of the bottom/right edge (previously up to ~500 rows per image were unmeasured; tiles went from 2880 to 4329); tiles with fewer than 3 grey levels get a deterministic all-class-1 fallback with NaN thresholds and a `threshold_fallback` flag (0 of 1443 BSE tiles triggered it); `qc kpi` refuses to join masks/thresholds whose config hash or tile positions differ from the current index; the audit recomputes every file SHA-256 (92/92 match the download inventory, the added Inlens file has no inventory row) and tolerates TIFFs without a resolution tag.
